# ژورنال معاملات

یه ژورنال ترید ساده و رایگان، مخصوص استراتژی‌های Breakout / Fake Breakout / Candle-Setup. کاملاً استاتیکه (HTML/CSS/JS خالص)، بدون بک‌اند و بدون هزینه هاست — روی GitHub Pages میزبانی می‌شه.

## مهم: داده‌ها کجا ذخیره می‌شن؟

همه‌چیز داخل `localStorage` همون مرورگری که ازش استفاده می‌کنی ذخیره می‌شه. یعنی:
- بین دستگاه‌ها یا مرورگرهای مختلف sync نمی‌شه.
- اگه کش مرورگر رو پاک کنی، داده‌ها از بین می‌رن.

پس هر چند وقت یک‌بار از دکمه **«خروجی اکسل»** بالای صفحه بک‌آپ بگیر.

> توجه: دیگه دکمه «پاک‌کردن همه» توی برنامه نیست. اگه لازم شد همه داده‌ها رو پاک کنی، از تنظیمات مرورگر برو توی بخش داده‌های سایت (Site Data) همین صفحه و پاکش کن، یا از Developer Tools کنسول بزن: `localStorage.clear()`.

## راه‌اندازی روی GitHub Pages (رایگان)

1. یه ریپازیتوری جدید توی گیت‌هاب بساز (مثلاً `trade-journal`).
2. سه فایل `index.html`، `style.css` و `app.js` رو (که همین پوشه هستن) به ریپو push کن.
   ```bash
   git init
   git add .
   git commit -m "trade journal v1"
   git branch -M main
   git remote add origin https://github.com/USERNAME/trade-journal.git
   git push -u origin main
   ```
3. توی گیت‌هاب برو به `Settings → Pages`.
4. زیر «Build and deployment»، سورس رو روی `Deploy from a branch` بذار، برنچ `main` و پوشه `/ (root)` رو انتخاب کن، بعد `Save`.
5. بعد از چند دقیقه، سایتت روی این آدرس در دسترسه:
   ```
   https://USERNAME.github.io/trade-journal/
   ```

هیچ build step یا dependency‌ای لازم نیست — فایل‌ها همون‌طوری که هستن سرو می‌شن.

## بخش‌های برنامه

- **داشبورد**: نرخ برد، مجموع R، اکسپکتنسی، Profit Factor، میانگین R برد/باخت، بهترین و بدترین استریک، منحنی سرمایه، عملکرد به‌تفکیک استراتژی، هیستوگرام توزیع R، عملکرد بر اساس سشن و جهت، شمارنده هشدارهای انضباطی — همه با فیلتر بازه تاریخ.
- **ثبت معامله**: فرم کامل شامل چک‌لیست تأییدها (روند 4 ساعته، BTC، BTC Pair، HWC/MWC/LWC، شکست سطح 4H/1D، حجم، شکل کندل، RSI، بسته‌شدن کندل، رنج/آخر هفته)، جزئیات تکمیلی (نوع پوزیشن/خروج، حالت ذهنی، نحوهٔ بسته‌شدن معامله، اشتباهات)، سه فیلد لینک اسکرین‌شات (15M/1H/4H)، و تشخیص خودکار لحن FOMO توی جمله توجیه یا حالت ذهنی. وضعیت معامله با سه حالت **TP / SL / ریسک‌فری** ثبت می‌شه.
- **لیست معاملات**: فیلتر بر اساس استراتژی و وضعیت، با نمایش هشدارها، و دکمه «ادیت» برای ویرایش هر معامله ثبت‌شده (فرم با مقادیر قبلی پر می‌شه).
- **استراتژی‌ها و قوانین**: کاملاً قابل ویرایش — می‌تونی استراتژی جدید اضافه کنی، نام/رنگ/قوانین هر استراتژی رو تغییر بدی یا حذفش کنی، و سطوح ریسک (درصدها) رو هم از همون‌جا مدیریت کنی. هیچ‌کدوم توی کد نیست، همه‌چیز داخل مرورگر ذخیره می‌شه.
- **یادداشت‌ها**: بخشی مستقل از معاملات، برای حد ضرر/حد سود روزانه و هفتگی، به‌علاوه یه فضای یادداشت آزاد برای هر نکتهٔ کلی دیگه.

## خروجی اکسل

دکمه «خروجی اکسل» بالای صفحه یه فایل `.xlsx` با تمام معاملات و جزئیاتشون (تاریخ، نماد، استراتژی، جهت، R، هشدارها، یادداشت‌ها...) می‌سازه — برای اشتراک‌گذاری یا تحلیل بیشتر توی Excel/Google Sheets. این قابلیت از کتابخانه [SheetJS](https://sheetjs.com) (از طریق CDN) استفاده می‌کنه، پس برای کار کردنش نیاز به اتصال اینترنت داری؛ ولی بقیه برنامه کاملاً آفلاین کار می‌کنه.

## ورودی اکسل (وارد کردن معاملات قبلی)

دکمه «ورودی اکسل» بالای صفحه یه فایل `.xlsx`/`.xls` می‌گیره و سعی می‌کنه ستون‌هاش رو خودکار تشخیص بده. اسم ستون‌های زیر (فارسی یا انگلیسی، بزرگ/کوچک فرقی نداره) شناسایی می‌شن:

| فیلد | اسم‌های قابل‌شناسایی |
|---|---|
| تاریخ | تاریخ, date, date & time |
| نماد | نماد, symbol, pair, ticker, position #, coin |
| استراتژی | استراتژی, strategy, strategy name, setup — اگه استراتژی‌ای با این اسم نداشته باشی، خودکار به تب «استراتژی‌ها و قوانین» اضافه می‌شه |
| جهت | جهت, direction, side |
| سشن | سشن, session |
| قیمت ورود | قیمت ورود, entry |
| حد ضرر | حد ضرر, stop |
| درصد ریسک | درصد ریسک, risk%, risk (%) — هم فرمت کسری (0.0025) هم فرمت درصد مستقیم (0.5) رو تشخیص می‌ده |
| وضعیت | وضعیت, outcome, result, trakings — مقادیری مثل win/loss/tp/sl/stopped/برد/باخت هم شناسایی می‌شن؛ اگه وضعیت مشخص نبود ولی R محقق‌شده داشت، از روی مثبت/منفی بودنش حدس زده می‌شه |
| R محقق‌شده | R, RR, realized r, risk/riward |
| یادداشت | یادداشت, notes, discription |

ستون‌های اضافه‌ای که فیلد اختصاصی توی برنامه ندارن (مثل تأییدهای مختلف، حالت ذهنی، اشتباهات، لینک اسکرین‌شات‌ها) گم نمی‌شن — خودکار به انتهای یادداشتِ همون معامله اضافه می‌شن تا هیچی از دست نره. اگه ستون «حالت ذهنی» مقدار «fomo» داشته باشه یا ستون «اشتباهات» به ورود قبل از بسته‌شدن کندل اشاره کنه، هشدارهای مربوطه (FOMO / ورود زودهنگام) هم خودکار فعال می‌شن.

ردیف‌هایی که تاریخ یا نماد ندارن (مثلاً ردیف‌های خالی یا تیترهای بخش‌بندی) رد می‌شن و تعدادشون توی پیام نهایی گفته می‌شه.

اگه فایلت ستون‌های خیلی متفاوتی داره و درست شناسایی نشد، ساده‌ترین راه اینه که اسم ستون‌ها رو توی خود فایل اکسل به یکی از اسم‌های بالا تغییر بدی و دوباره امتحان کنی.

## شخصی‌سازی بیشتر

- استراتژی‌ها، قوانین و سطوح ریسک رو دیگه لازم نیست توی کد ویرایش کنی — همه از تب «استراتژی‌ها و قوانین» قابل مدیریتن.
- برای تغییر کلمات هشدار FOMO، آرایه `FOMO_WORDS` توی `app.js` رو ویرایش کن.
- رنگ‌ها و فونت‌ها توی ابتدای `style.css` (بخش `:root`) تعریف شدن.

## توجه درباره باز کردن فایل‌ها

`index.html`، `style.css` و `app.js` باید همیشه توی یک پوشه کنار هم باشن — اگه فقط `index.html` رو جدا دانلود کنی، ظاهر و عملکرد برنامه درست نمایش داده نمی‌شه.
